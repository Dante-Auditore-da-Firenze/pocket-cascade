# Pocket Cascade Visual Concepts

Four isolated interface studies, created on 2026-09-23 for comparison before
choosing a production art direction. No concept is selected or applied to the
game. These previews do not read or write browser storage or native saves.

## Round Two: Art-First Stills

Following feedback that the first four directions lacked distinctive character
and used oversized display type, the 2026-09-24 exploration focuses on two
original illustrated machines rather than more interface variants:

- [A: The Curio Press](http://127.0.0.1:5173/tools/concepts/studies.html?study=press):
    sculpted red enamel, an exposed flywheel, a physical score register, and an
    attached parts drawer. A heavier, tactile countertop object.
- [B: The Glass Engine](http://127.0.0.1:5173/tools/concepts/studies.html?study=glass):
    an oval glass face, metal ribs, perimeter winding gears, a base-mounted register,
    and a fold-out rack. A more unusual, open instrument silhouette.
- [Compare both stills](previews/round-two/comparison.png).

Each full-size still is a 2400x1500 WebP (quality 90); its viewer also links to
a PNG close-up of the new gadget artwork. These are **still-image art studies**,
not interactive machines,
full mobile UI proposals, earned runs, or adopted production designs. Both use
the same illustrative commission, score, inventory, and 46-socket arrangement.
Frame/rail shapes are proposed art and would require gameplay/readability checks
before implementation. The score/target type is 24-25 logical pixels, with the
commission number at 27; no giant permanent score display.

All machine and gadget art is newly authored Canvas2D drawing in `studies.mjs`:
original paths, material shading, surface texture, contact shadows, and detail.
It reuses the preview-only local fonts and licenses listed below. No reference
game images, paid art, new downloads, image-generation service, or additional
package was used. The original four concepts and game source remain unchanged.

With the existing Vite server running, regenerate and verify the stills:

```powershell
node tools/concepts/capture-studies.mjs
```

The script checks both nonblank images, 46 drawn sockets each, bounded score type,
text inside image bounds, and the viewer's two selectors at desktop/mobile widths.
It blocks storage access and rejects browser errors/external requests. This checks
image/viewer integrity, not subjective appeal, full accessibility, collision geometry,
or finished mobile usability. Output and evidence are in `previews/round-two/`.

## Directions

| Concept | Intent | Main Tradeoff |
| --- | --- | --- |
| Tin Toy | Red enamel, a green score register, rounded mechanical silhouettes, and a molded parts tray. Warm and tactile without adopting a casino theme. | More playful and object-like; less austere than the current machine. |
| Signal Arcade | Acid-yellow scores, coral/cyan accents, flat expressive part art, and an open high-contrast composition. | The strongest visual energy, but needs restraint during busy cascades. |
| Field Notes | Blue/red printed linework, graph paper, serif typography, and sketch-like gadgets. | More illustrative and handmade; quieter than the arcade direction. |
| Precision Instrument | A light machined console, inset score display, compact part rack, and purposeful industrial lettering. | Crisp and tactile, but more restrained than the other alternatives. |

## Prototype Boundary

The common commission-6 machine is an authored visual fixture, not a claimed
earned campaign. Initial score, last-cascade summary, credit balance, and the
reward scene are presentation samples. Clicking Drop Token uses the unchanged
shared `DropSimulation` at 120 Hz and adds its actual payout to the in-memory
sample. Rewards are visual selection previews, not a complete shop/economy.

This is not a replacement game: no campaign advancement, paid shop, full tuning
flow, save/import/export, audio, controller implementation, or settings suite.
Reduced preview motion suppresses trails and effect expansion, not the moving
token itself. No live run is loaded or altered. The production entry, build
configuration, game source, dependencies, and original shipped art are unchanged.

## Artwork and Fonts

All concept part and cabinet illustrations are original Canvas2D work in
`visuals.ts`. No screenshots, illustrations, shaders, or assets from Balatro or
the other research references are reused. UI icons use the existing Lucide React
dependency; DM Sans and Barlow Condensed use the project's existing local fonts.

Two additional preview-only fonts were downloaded from the official Google Fonts
repository. Both are served locally and include their SIL Open Font License:

- [Fraunces source](https://github.com/google/fonts/tree/main/ofl/fraunces),
  [local license](Fraunces-OFL.txt).
- [Space Grotesk source](https://github.com/google/fonts/tree/main/ofl/spacegrotesk),
  [local license](SpaceGrotesk-OFL.txt).

No paid service, generated-image service, package installation, or external
runtime request is required. Font downloads were checked for valid TrueType
headers and accompanying OFL license text; no signature verification is claimed.

## Reproduce Checks

Start the normal development server without resetting its player save, then run:

```powershell
node tools/concepts/capture.mjs
```

Set `CONCEPT_ORIGIN` if the server uses a different origin. The script launches
its own isolated browser context, blocks all Storage reads/writes, rejects
external requests, checks canvas pixels and board proportions, validates text
fit and horizontal bounds, exercises real preview cascades/placement/reset, and
captures all four concepts at three viewport sizes. It also captures reward
views and creates the two comparison sheets using Sharp.

The concept-only TypeScript check is:

```powershell
node node_modules/typescript/bin/tsc --noEmit --jsx react-jsx --module ESNext --moduleResolution Bundler --target ES2022 --lib ES2022,DOM --esModuleInterop --skipLibCheck tools/concepts/preview.tsx tools/concepts/visuals.ts
```

Actual result: twelve concept/viewport combinations passed; no browser errors,
external runtime requests, persistent-storage access, horizontal overflow, or
score/target overlap detected. Captures were visually inspected. This is concept
validation, not a new production-game regression or hardware certification.
